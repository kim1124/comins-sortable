# 0.1.7 배포 후보와 검증 상태

기준일: 2026-10-25 KST. 상태: 로컬 배포 준비, 미게시.
제품 기준: `4fcdba1`에 포함된 `676df18`의 렌더링·메모리 수정.
패키지 버전·문서 자동화는 그 이후의 로컬 변경이다. 원격 push, staging,
npm publish, 태그·GitHub Release는 이 작업에 포함하지 않는다.

## 포함되는 변경

- 네 어댑터 공통 `placeholder.render`와 `dragOverlay.render`. 동기 DOM 렌더러의
  생성·의미 변경 시 update·destroy를 제공한다. Core가 임시 host와 좌표·정리를 소유한다.
  framework 전용 component/hook/composable API는 추가하지 않는다.
- 장기 scope의 세션 이력 누적 제거, 완료된 Core/Vanilla disposer 참조 해제,
  동기 cleanup 실패·재진입 시 나머지 자원 정리 유지.
- 수락한 명시적 mouse handle 입력에서 활성화 대기 중 `selectstart` 억제.
  기존 Selection은 지우지 않고 일반 본문 선택은 유지한다.
- CHANGELOG 기반 README 상단·문서 인덱스·최신 릴리스 문서 동기화와 불일치 검사.

## Safari Vue DOM 보유에 대한 최종 판단

2026-10-24 전용 재현에서 100회 Vue mount/unmount 후 Vue 앱·컴포넌트와 종료된
Sortable controller/binding/callback은 회수됐다. 남은 DOM 155개(31개 × 5구간)는
JS ID와 native Node 주소를 교차 검증했다. Reader 전역 247개의 native map·Strong
handle·InjectedScript 쌍과 JS 보유 경로가 일치했다.

`WebInjectedScriptManager → Strong handle → InjectedScript → Reader Window →
Reader DOM cache → native DOM root` 경로로 보유됐다. 같은 페이지·같은 PID에서
새로고침 없이 Inspector를 닫고 재연결 후 GC가 포함된 스냅샷을 수집하자 Reader는
0개였고, 이전 native DOM 주소 155개는 동일 타입 할당에서 모두 사라졌다.
이 재현은 Sortable Vue의 정리 누락을 뒷받침하지 않으며 추가 제품 수정 사유가 아니다.
원본 그래프·주소·검증기는 ignored 로컬 진단 자료에 보존한다.

과거 DOM 124개 자체의 native 주소는 복원하지 못했다. 숫자 JS ID는 snapshot 순서로
재구성해 독립 native 포인터와 교차 검증했다. C++ 필드 의미는 공개 소스로 보강했으며
동일 빌드 DWARF 또는 GC root-reason 덤프는 수집하지 않았다. 모든 환경의 무누수나
프로세스 RSS의 기준 복귀를 보장하지 않는다. 전체 Safari 덤프·보안 설정 변경은 없었다.

## 알려진 제한과 남은 배포 게이트

- 드래그 도중 transform 변경은 Chromium/Firefox/WebKit 진단 36건에서 실패했다.
  정적인 2D transform 지원과 구분하며 0.1.7에서 해결됐다고 표현하지 않는다.
- 과거 Safari 제목 전용 선택 잔류와 mouse handle 수정은 구분한다. 이번 native
  메모리 검증은 모든 모드·어댑터의 제목 선택 회귀 통과를 증명하지 않는다.
- 3D perspective, 키보드 정렬, framework 전용 렌더러 API, 실물 모바일 장치 인증은
  이 버전에 포함하지 않는다.
- 배포 후보의 fresh 검증은 아래 결과 및 작업 보고서에 기록한다. 정확한 tgz의
  파일 경계·라이선스·Gitleaks·소비자 검사와 원격 CI/staging/provenance는 별도 단계다.
- 새 버전 준비 방식은 [문서 동기화 절차](./release-docs.md)를 따른다.

## 2026-10-25 새 후보 검증

제품 소스 변경 없이 0.1.7 manifest·문서·자동화가 포함된 격리 사본을 만들었다.
미커밋 overlay를 파일별 SHA-256으로 기록하고, 생성물·공유 의존성이 없는 상태에서
`npm ci --ignore-scripts` 후 검증했다. 새 후보 커밋이나 원격 CI 검증으로 표현하지 않는다.

- PASS: 공개 production Playground 749건(Chromium/Firefox/WebKit 및 touch emulation).
  다른 세션의 4003 포트를 사용하지 않고 별도 4067 포트에서 같은 suite를 실행했다.
- PASS: 성능·메모리 suite 13건. 네 어댑터 반복 입력·중첩 재마운트와 Core/Vanilla의
  장기 scope·종료 disposer 보유 검사를 포함한다. 성능 suite는 다른 build/browser
  게이트와 동시에 실행하지 않았다. Safari의 native 검증을 대체하지 않는다.
- PASS: 동일한 0.1.7 tgz의 파일 경계·exports·라이선스·추출 Gitleaks·소비자 검사.
  최소 Vue 및 개발 Vue SFC 양성·음성 타입 검사를 포함한다.
- PASS: Safari 분석 도구 회귀 11건. 이 도구 통과가 전체 Safari 무누수 판정은 아니다.

- PASS: 마지막 자동화 수정 후 전체 verify — 정책 84건, 단위 331건,
  라이선스·타입·빌드·Vue SFC 검사.
- PASS: Core 브라우저 301건. CI 모드로 기존 서버 재사용 없이 검증했다.
- PASS: 정확한 tgz의 128개 파일이 최종 빌드 및 배포 대상 문서와 byte 단위로 일치.

패키지 SHA-256과 환경 실패·복구 내역은
[배포 준비 보고서](../../reports/2026-10-25-0.1.7-release-preparation.md)에 기록한다.
레지스트리 DNS 오류·sandbox listen 차단은 허용된 실행 환경에서 재실행해 해결했으며,
기본 npm 캐시 쓰기 차단은 임시 캐시로 해결했다. 허용치를 변경하지 않았다.
