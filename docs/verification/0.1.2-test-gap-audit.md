# 0.1.2 테스트 누락 분석

> 이 문서는 단계별 과거 조사·수정 기록이다. 최신 검증 및 커밋 상태는
> [0.1.2 후보 검증 현황](./0.1.2-release-candidate.md)을 참고한다.

이 문서는 반복적으로 수동 재현에 실패했던 테이블 행·열 예제와 0.1.2에서
추가한 고급 정렬 예제의 테스트 신뢰성을 검토한 기록이다.

## 결론

기존 자동화는 드래그 결과 모델을 주로 확인했지만 사용자가 실제로 보는 DOM
순서, Placeholder 위치, 빠른 Pointer release, 화면 경계에 가려진 대상을
독립적으로 충분히 확인하지 않았다. 따라서 테스트 통과를 테이블 행·열 예제의
실사용 정상 동작 근거로 확대 해석할 수 없었다.

테이블 행·열 Playground 경로는 0.1.2 범위에서 제거했다. Core의 table DOM
transaction 회귀 테스트는 유지하지만, 이를 사용자용 테이블 정렬 기능 지원
근거로 사용하지 않는다.

## 확인된 테스트 누락

1. 테이블 테스트는 한 가지 이동만 수행한 뒤 Playground bridge의 모델 순서를
   확인했다. 실제 `tr`/`th`/`td`의 시각 순서, Placeholder 위치 및 열 heading과
   detail cell의 동기화를 별도로 단언하지 않았다.
2. 드래그 도우미는 Pointer 활성화 프레임과 목표 Placeholder가 안정될 때까지
   기다렸다. 사람이 빠르게 놓는 경우처럼 첫 animation frame 전에 발생하는
   `pointerup` 경로가 누락됐다.
3. Source와 destination이 sticky header 또는 viewport 경계에 가려졌는지
   측정하지 않았다. 처음 보이는 요소 기준 좌표만 사용해 맨 위·맨 아래 이동의
   실제 포인터 조건을 충분히 재현하지 못했다.
4. 경로 수와 브라우저별 통과 수는 많았지만, first/last 이동·DOM 결과·빠른
   release 같은 입력 차원별 coverage가 명시되지 않았다.
5. 다중 이동의 시작 위치는 원본 목록 인덱스, 충돌 위치는 선택 항목을 제외한
   목록 인덱스를 사용했다. 값이 우연히 같으면 Placeholder 갱신이 생략되는
   조건을 단위 테스트가 다루지 않았다.

## 0.1.2 보강 사항

- 첫 animation frame 전 `pointerup`과 마지막 queued destination commit을 Core
  단위 테스트로 고정했다.
- 드래그 도우미가 source와 destination의 viewport 위치를 확인하고 sticky
  header 또는 하단 경계에 가려진 경우에만 안전한 중앙 위치로 이동한다.
- 그리드는 20개 항목을 사용해 첫 위치와 후반 위치 이동을 네 어댑터와 세
  브라우저에서 확인한다.
- 다중 선택은 Ctrl/Command 추가 선택, Shift 범위 선택, 선택 스타일, 원래 순서
  보존 이동 및 선택 제외 인덱스의 Placeholder 위치를 확인한다.
- Thresholds는 control 실시간 변경과 실제 reorder를 함께 확인한다.
- Swap은 대상 강조 표시와 정확히 두 항목만 교환되는 결과를 확인한다.
- 모든 문서화된 Playground 경로가 네 어댑터에서 마운트되고 코드 보기 진입점이
  노출되는지 확인한다.

## 잔여 경계

- Playwright WebKit 통과는 실제 macOS Safari 및 OS 수준 포인터 입력 인증을
  대체하지 않는다.
- 테이블 행·열은 경로가 제거된 상태이며 0.1.2 지원 기능으로 인증하지 않는다.
- 릴리스 전에는 Chrome·Firefox·WebKit 자동 게이트 외에 실제 브라우저에서
  빠른 release와 first/last 이동을 한 차례 수동 smoke test한다.

## 2026-09-08 추가 검증

위 보강 기록은 이전 구현 시점의 기록이다. 이번에는 요청한 source의 실제
활성화와 모델·DOM 일치를 검사하고, polling 내부의 반복 포인터 입력을 제거했다.
이 결과 이전 통과 수를 현재 기능 정상 동작의 근거로 사용할 수 없음을 확인했다.

- Nested 부모 중앙 입력은 네 어댑터 모두 요청한 `todo/research` 대신
  `child/review`를 활성화했다. 식별자 회귀를 먼저 4/4 실패시킨 뒤, 노출된
  영역의 hit-test와 실제 drag-start source 검사로 수정했다. 부모 정렬 및
  child 보존은 세 브라우저에서 통과했다.
- Move는 실제 원본, Copy는 공개 drag-start callback의 area/item과 별도
  preview를 검사한다. Handle 역시 같은 활성화 도우미를 사용한다.
- Thresholds는 0.2/0.8 및 invert 조합에 동일 입력을 적용하여 reorder와
  no-op의 차이를 확인한다. Tree 왕복·Swap·Accept reset/remount는 모델과
  DOM을 함께 검사한다. 주요 작업에는 source/destination/item도 검사한다.
- 다중 선택의 독립 시나리오는 새 페이지에서 시작한다. 데이터 초기화가
  선택 상태까지 초기화한다고 가정하지 않는다.
- 순환 거부는 실제 부모를 드래그하며, 공개 `parent` 관계를 가진 별도 위치의
  자식 host를 사용한다. 이동 중인 부모 내부의 자식을 다른 항목으로 대신
  활성화하는 테스트가 아니다.
- 종료 검사는 등록된 host, 등록 해제 후 남은 Vanilla DOM, Svelte unmount로
  제거된 DOM을 명시적으로 구분한다. 모델 원복과 DOM의 복원 또는 제거를
  각각 검사한다.

### 새로 드러난 제품 결함

1. `src/core/scope.ts`의 `directNonItemHit()`는 area 기준 선택자
   `:scope > *`를 자식의 `matches()`에 전달한다. 브라우저에서 area의
   `querySelectorAll()` 결과에는 들어가지만 자식의 `matches()`는 false다.
   Vanilla·Svelte의 정상 항목을 비정렬 슬롯으로 오판하여 기본 이동을
   거부하고, 순환 거부 사유도 `nested-cycle` 대신 `not-accepted`가 된다.
   실제 hit-test 및 거부 속성과 세 브라우저 회귀로 확인했다.
2. 같은 area에서 드래그 중 외부 스크롤이 발생하면 좌표 캐시를 갱신하지
   않는다. Core 자체 자동 스크롤의 갱신만 구현되어 있다. Grid 마지막→처음
   이동에서 포인터는 `grid-1` 위에 있지만 placeholder는 `grid-19` 앞에 남는다.
   네 어댑터·세 브라우저에서 실패하고, 성능 시나리오도 같은 지점에서 중단된다.
   WebKit 다중 선택 3건도 스크롤 후 목적지 불일치이며, 같은 원인인지 제품
   수정 후 확인해야 한다.

## 2026-09-08 주요 결함 수정 후 검증

앞 절의 실패는 수정 전 기록이다. 후속 구현에서 다음 결함을 수정했다.

- Core의 slot 판정·Swap 대상·끝 삽입 경계는 등록 area에서 조회한 항목
  집합을 사용한다. 충돌 계산에서 제외한 source도 등록 항목으로 구분한다.
- Vanilla Copy는 분리된 요소의 기본 계약을 검사한 뒤, 실제 목적지에 삽입한
  요소의 선택자와 ID를 검증한다. 실패하면 소비자 change callback 전에
  삽입을 즉시 복원한다. footer 앞의 끝 삽입 경계도 보존한다.
- 외부 스크롤은 활성 세션의 window·ancestor offset을 추적하며 기존 포인터
  프레임에서 geometry를 갱신한다. 포인터 정지·즉시 드롭·늦게 도착하는 scroll
  이벤트를 처리하고, 자체 auto-scroll 알림이 중복 프레임을 만들지 않도록 한다.

새 테스트의 RED를 확인한 뒤 수정했고, 다음 최종 게이트를 통과했다.

| 검증 | 수정 후 결과 |
| --- | --- |
| `npm run verify` | 정책 50/50, 단위 235/235, 타입·build·public types 통과 |
| `CI=1 npm run verify:e2e` | 238/238 통과 |
| `CI=1 npm run verify:playground` | 216/216 통과 |
