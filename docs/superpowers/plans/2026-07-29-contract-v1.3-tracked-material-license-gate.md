# Comins Sortable Contract v1.3 Tracked-Material License Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adopt Comins Contract v1.3 in Sortable and add a deterministic, fail-closed license gate for tracked repository material without creating a package boundary.

**Architecture:** `LICENSE_SCOPE.json` records the reviewed pre-package state: no dependency manifest, copied or generated third-party code, or asset is currently tracked. `scripts/check-licenses.mjs` compares that state with Git's tracked paths, rejects malformed or non-empty baseline declarations, and blocks dependency manifests, conventional copied/generated paths, and asset file types until a separately reviewed evidence-aware gate update is made.

**Tech Stack:** Markdown, JSON, Node.js 24 ESM, Node built-in test runner, Git, GitHub Actions.

## Global Constraints

- Preserve the independent Sortable Git and CI boundary.
- Keep the approved management order: repository/instructions, Contract/scope/authority, security, licensing, module rules, implementation, verification, Git/PR, exact-artifact release, closure/reporting.
- Do not add `package.json`, a lockfile, npm commands, package archives, build commands, or publish automation.
- Treat package and exact-artifact release gates as not applicable until a maintainer approves a package boundary.
- Do not approve or suppress future third-party material through path exceptions; require exact source, version or revision, SPDX, use-surface, obligation, notice, and approval evidence in a separately reviewed gate change.
- Expose only the constant `license-check: failed` on checker failure.
- Preserve the module-owned product and package boundaries outside the managed
  `AGENTS.md` block; update only its repository validation command to include
  the new license gate.
- Do not commit, push, create a pull request, merge, or modify the primary worktree in this task.
