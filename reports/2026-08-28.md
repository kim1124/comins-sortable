## 잔여 이슈

- 실제 release tarball은 보호된 source merge 이후 단 한 번 생성하고, 추출
  Gitleaks 및 exact consumer smoke를 통과한 동일 artifact만 bootstrap publish한다.
- 최초 npm 공개는 maintainer web login 및 2FA가 필요하다. 공개 직후 exact
  `publish.yml`과 `npm` environment를 stage-only trusted publisher로 등록해야 한다.
- Playwright WebKit 결과는 실제 Safari 인증이 아니다. Physical touch 및 pen도
  이번 release 인증 범위에 포함하지 않는다.
- 기존 `favicon.ico` 404는 이번 UI 및 release 범위 밖으로 유지한다.

## 공개 후 사고 및 로컬 보완

- `comins-sortable@0.1.0` 공개 메타데이터에서 npm 계정의 비서비스 이메일이
  확인되어 즉시 unpublish했다. 정확한 버전과 tarball은 현재 404이며,
  레지스트리에는 이메일 필드 없는 unpublish tombstone만 남아 있다.
- `0.1.0`은 재사용할 수 없어 다음 공개 후보를 `0.1.1`로 변경했다.
- 기존 npm maintainer 검사가 이름만 비교하고 이메일을 버리던 원인을
  수정했다. 교체 검사는 provider-managed name/email과 authenticated profile,
  current registry maintainer, exact published metadata를 각각 fail-closed로
  검증하며 실제 identity 값을 출력하지 않는다.
- release workflow에 전체 reachable Git history identity 검사를 추가했다.
  현재 legacy main 이력은 이 검사에 실패하므로 이력 정리가 별도 승인되어
  완료되기 전에는 release가 차단된다.
- npm 계정 이메일 변경, repository/environment secrets 생성, trusted publisher
  등록, Git 이력 재작성, 재배포는 이번 로컬 코드 변경 범위에 포함하지 않았다.

## 0.1.1 bootstrap release closure 보완

- 점검 시각: 2026-08-28 22:57 KST
- npm registry는 `comins-sortable`을 `E404`로 반환했고, unpublish 시각은
  `2026-08-28T10:11:25.371Z`였다. 동일 이름의 새 버전 bootstrap은 24시간 제한
  해제 전까지 시도하지 않는다.
- 현재 재작성된 `main`의 전체 reachable Git identity 검사는 통과했다. 위의 legacy
  이력 차단 기록은 사고 당시 상태이며 현재 차단 요소가 아니다.
- 기존 exact-version 검사는 GitHub Actions trusted publisher만 허용하여, npm package가
  없는 상태에서 필수인 대화형 bootstrap의 공개 메타데이터를 정상적으로 닫을 수 없는
  계약 누락이 있었다.
- `check:npm-bootstrap -- <exact-version>`을 추가했다. 이 검사는 exact maintainer와
  직접 publisher identity, 빈 author/contributor 메타데이터를 요구한다. 후속 staged
  release용 `check:npm-identity -- --version <exact-version>`은 기존대로 GitHub Actions
  trusted publisher와 approver를 요구한다.
- focused release/package gate `13/13`, `npm run verify`의 policy `41/41`과 unit
  `202/202`, typecheck, build, public type fixture가 통과했다.
- 동일 제품 소스에서 Core E2E `205/205`, Playground E2E `117/117`이 통과했다.
  이후 변경은 release checker, package script, 보안/변경 기록 및 테스트에만 한정되어
  브라우저 제품·fixture·dependency 상태는 변경되지 않았다.
- 로컬 환경에는 `COMINS_NPM_PUBLIC_NAME`과 `COMINS_NPM_PUBLIC_EMAIL`이 설정되어 있지
  않아 실제 npm profile 검사는 수행하지 않았다. identity 값은 repository나 로그에
  저장하지 않는다.

## 0.1.1 공개 및 후속 검증

- 공개 시각: 2026-08-30 00:04:37 KST
- 보호된 `main`의 `c648e7e`에서 생성한 `comins-sortable@0.1.1`을 maintainer
  web login 및 2FA로 bootstrap publish했다. 최초 요청은 npm tombstone 처리 중
  `E409`로 거부되었고, 무버전 상태와 수정 시각이 5분간 안정화된 뒤 동일 artifact로
  한 번만 재시도해 성공했다.
- 공개 registry의 `latest`와 exact version은 모두 `0.1.1`이며, package file은
  116개다. 공개 maintainer 및 direct publisher identity, 빈 author/contributor
  메타데이터를 값 비노출 방식으로 검증했다.
- 승인 artifact와 공개 tarball은 바이트 단위로 동일하다. SHA-256은
  `0eef396f80ba64f09931d1088e12f635ce80601dfe980310c16f8c7c15afe279`, npm
  shasum은 `b873016f0c462f7f456fbd7b02919d269d288c77`이다.
- 공개 tarball Gitleaks, exact consumer smoke, public export 및 CSS entry 확인을
  통과했다. `npm audit signatures`는 공개 package의 registry signature 1건을
  검증했다. 대화형 bootstrap이므로 provenance attestation은 없으며, 후속
  GitHub Actions trusted publishing부터 자동 생성된다.
- Trusted Publisher는 GitHub Actions, `kim1124/comins-sortable`, `publish.yml`,
  `npm` environment, `createStagedPackage` 단일 권한으로 등록된 것을 npm CLI로
  다시 읽어 검증했다. GitHub `npm` environment의 reviewer/branch policy와 두
  identity secret 이름도 확인했다.
- 공개 소스 `c648e7e`의 GitHub Verify run `33178684567`은 성공했고, local main,
  origin/main 및 공개 소스 SHA가 일치한다.

## 0.1.1 잔여 closure

- package publishing access에 `npm access set mfa=publish comins-sortable`을
  Galaxy/WebAuthn 인증으로 적용했고 명령은 성공했다. 이후 대화형 publish에는
  2FA가 필요하며 automation token은 publish에 사용할 수 없다. Trusted Publisher의
  OIDC staged publishing 경로는 이 제한의 적용 대상이 아니다.
- 공개 후 README, CHANGELOG, policy assertion 및 이 보고서를 원격 `main`에
  반영하기 전까지 release 상태는 `Published`이며 `Closed`가 아니다.
- Playground WebKit 결과는 실제 Safari 인증이 아니다. Physical touch 및 pen도
  이번 release 인증 범위에 포함하지 않는다.
- tag와 GitHub Release는 생성하지 않았다.
