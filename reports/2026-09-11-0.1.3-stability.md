## 확정 범위

- `selectedClass` 변경 시 이전 표시를 제거하고, 영역 해제와 scope destroy 시
  다중 선택 표시·선택 ID·범위 기준점을 정리한다. 다른 영역과 소비자 클래스는 보존한다.
- 자동 스크롤을 경과 시간에 비례하도록 바꾸고 60Hz의 기존 최대 속도를 유지한다.
  중복 콜백의 추가 이동과 긴 프레임 중단 후 과도한 이동을 방지한다.
- RTL 컨테이너와 페이지의 음수 수평 스크롤 범위를 지원한다.
- 앞서 정리한 README 및 npm description/keywords를 이어받고 관련 사용 문서를 보완한다.

공개 옵션, 의존성, 패키지 버전은 이번 구현에서 변경하지 않는다. 실제 버전 변경과
원격 반영·배포는 검증 결과 확인 후 릴리스 단계에서 진행한다.

## 검증 계획

1. 선택 클래스 교체·해제·재등록과 자동 스크롤 시간·RTL 경계를 단위 테스트로 재현한다.
2. 원인을 수정하고 집중 테스트의 RED → GREEN을 확인한다.
3. 실제 브라우저 RTL 회귀 및 기존 패키지·Playground·성능 게이트를 실행한다.
4. 실패 원인, 최종 결과와 미실행 범위를 아래에 기록한다.

## 구현 결과

- `updateArea`에서 이전 옵션으로 선택 표시를 지운 뒤 새 옵션을 적용한다.
  item selector 변경으로 대상에서 제외되는 기존 항목의 표시도 정리한다.
- 등록 해제와 scope destroy가 공통 선택 정리 함수를 사용한다. 같은 영역 ID로
  재등록할 때 이전 선택과 Shift 기준점이 되살아나지 않는다.
- 자동 스크롤은 단조 시간으로 이동량을 계산한다. 첫 이동은 기존 60Hz 한 프레임
  기준이며, 이후 동일 시각의 콜백은 추가 이동하지 않는다. 프레임 지연은 최대
  50ms까지만 반영하고, 영역 이탈·비활성화·드래그 종료 시 시간을 초기화한다.
- RTL의 수평 범위를 `[-maximum, 0]`으로 처리하여 왼쪽 이동과 오른쪽 경계를
  지원한다. 컨테이너 우선순위와 페이지 fallback은 유지한다.
- README의 고정 현재 버전 문구를 제거하고 npm 패키지 링크를 사용한다.
  영어·한국어 기능 문서는 다음 릴리스 보완과 현재 배포된 0.1.2를 구분한다.
  변경 기록은 `Unreleased`에 기록했다.

## 재현 및 최종 검증

- 수정 전 집중 테스트 20건 중 12건이 예상대로 실패했다. 선택 클래스 교체,
  등록 해제·파괴·재등록, 같은 시간의 중복 스크롤, 60/120Hz 이동량 차이,
  RTL 음수 좌표 처리 실패를 확인했다.
- 수정 후 시간 초기화와 item selector 변경 검증까지 포함한 집중 테스트
  23건이 통과했다. 60/120Hz 비교는 결정적인 가상 시계로 Core와 scope의
  프레임 예약까지 검증했으며, 실제 고주사율 디스플레이 측정은 아니다.
- 브라우저 회귀는 네 프레임워크의 RTL 컨테이너 양방향 이동·취소, RTL 페이지
  양방향 이동, Vanilla 소비자 DOM의 클래스 교체·destroy 정리를 확인한다.

브라우저 게이트는 Chromium, Firefox, WebKit에서 실행했다. Playground와 성능
검증은 저장소의 기존 4003 Vite 개발 서버를 재사용했으며, production build는
별도로 통과했다. 드래그 전후 본문 선택·복사와 재드래그 회귀도 포함한다.

성능 검증은 25개 React 경로의 반복 실행이다. warm → repeated에서 Heap은
6.78 → 6.94 MB, DOM Nodes 471 → 471, Event Listeners 381 → 381,
live nodes 150 → 150이었다. 장시간 누수 부재를 보증하는 결과는 아니다.

초기 검증의 실패는 다음과 같이 분류하고 해소했다.

- 테스트 타입: 구조적 fake DOM의 타입 단언을 `unknown` 경유로 보정했다.
- 테스트 조건: RTL 페이지의 본문 높이가 0이면 실제 수평 스크롤 영역이
  생성되지 않았다. 로컬 Chromium에서 크기를 측정하여 확인하고 테스트에
  최소 높이와 overflow 전제 검증을 추가했다.
- 실행 환경: 기본 정책 테스트가 browser fixture 번들을 재생성하므로 브라우저
  테스트와 동시 실행 시 로딩이 실패했다. 전체 게이트는 순차 실행으로 통과했다.
- 실행 환경: 별도 브라우저 진단의 Mach 권한 및 테스트 서버의 listen EPERM은
  허용된 실행 환경에서 다시 확인했다.
