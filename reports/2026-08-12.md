## Task 7 요약

- React·Vue·Svelte adapter가 공유할 private framework binding registry와 controlled transaction을 추가했다.
- `itemKey` property/callback에서 안정적 item ID를 해석하며, 누락 ID를 index로 대체하지 않고 `MISSING_ITEM_ID`로 거부한다.
- registry는 area ID와 동일 group의 item ID를 등록 시 검증하고, unregister 시 binding 및 그 callback 참조를 제거한다.
- transaction은 `change.orders` 순서로 affected setter를 정확히 한 번 호출한 후 root `onChange`를 한 번 호출한다. setter 또는 root callback의 partial failure에는 모든 원래 array를 복원한다.
- 명확화된 C 계약을 적용했다. `confirm`의 ID order는 최신 framework state의 `getItems()`와 `getItemId()`로만 비교하고, DOM은 placeholder 제외 direct child 수가 item 수와 같은지 확인하는 structural guard로만 사용한다. `getElement() === null`은 false다.
- public package export, framework import, runtime dependency는 추가하지 않았다.

## Task 7 Review Fix Round 1

- registry registration과 transaction snapshot 경계에서 affected group의 모든 current binding을 한 번씩 scan하여, 등록 뒤 발생한 same-area 및 cross-area duplicate ID를 `DUPLICATE_ITEM_ID`로 거부하도록 보강했다.
- group validation이 arrays를 모두 한 번 읽은 뒤 수행되므로 apply의 affected binding `getItems()`는 validation과 snapshot에 걸쳐 정확히 한 번만 호출된다. validation failure에는 setter, root callback, pending original snapshot retention이 없다.
- apply setter와 rollback은 registry 재조회 대신 initial snapshot의 captured binding을 사용한다. 첫 setter가 다른 area를 unregister/re-register해도 replacement binding은 update 또는 rollback으로 오염되지 않는다.
- disposer는 area ID와 identity token만 capture하며 binding callback/element/adapter state 참조를 closure에 보관하지 않는다.
- rollback setter failure가 있어도 remaining original restore를 계속하고 최초 apply/root callback 오류를 유지하는 기존 동작을 committed regression으로 고정했다.
- Task 7 brief의 confirm 문구를 확정된 C 계약(state `getItems`/`getItemId` ID order + placeholder 제외 direct-child count structural guard, null false)으로 최소 수정했다.
