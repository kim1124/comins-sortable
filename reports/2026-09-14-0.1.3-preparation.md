## 실제 Safari 확인 범위

Safari 26.6.2에서 위 tarball을 추출한 Vanilla/Core API를 임시 화면에 로드하고,
CUA 네이티브 마우스·키보드로 아래 흐름을 확인했다. 패키지 코드는 수정하지 않았다.

1. 항목 클릭: 선택 표시 1, 이전 클래스 1, 새 클래스 0.
2. 선택 클래스 변경: 선택 표시 1을 유지하면서 이전 클래스 0, 새 클래스 1.
3. destroy: 선택 표시·이전 클래스·새 클래스 모두 0, 소비자 카드 DOM 유지.
4. 새 sortable 등록 후 두 번째 카드를 선두로 이동: 순서 `2, 1, 3, ...`, change 1.
5. 이동한 카드의 본문 일부를 직접 선택하고 Cmd+C/Cmd+V:
   입력 필드에서 `Value` 확인. 텍스트 선택으로 추가 정렬이 발생하지 않았다.
6. 새로고침 없이 원래 첫 번째 카드를 다시 선두로 이동:
   순서 `1, 2, 3, ...`, change 2.

RTL 컨테이너에서는 짧은 드래그와 정렬을 확인했으나, 해당 입력 도구는 누른 채
포인터를 가장자리에 유지하는 단계를 별도로 제공하지 않는다. 이 조작에서 실제
음수 offset을 관찰하지 못했으므로 Safari RTL 자동 스크롤을 통과 처리하지 않는다.
RTL 컨테이너·페이지의 양방향 자동 스크롤은 Chromium·Firefox·WebKit E2E로
확인했다. WebKit 결과는 실제 Safari의 해당 입력 인증을 대신하지 않는다.

임시 Safari 탭과 임시 서버를 종료했으며 기존 Playground 탭은 보존했다.
Safari의 세 framework adapter, OS 보조키를 누른 채 클릭, 실제 touch/pen 기기,
실제 120Hz 디스플레이는 이번 직접 조작 범위에 포함하지 않았다.
