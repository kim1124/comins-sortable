## 변경 및 호환성

이번 릴리즈는 공개 API와 의존성을 유지하는 결함 수정이다.

- 드래그 시작 대비 출발·도착 목록의 순서, ID 또는 DOM 항목이 달라지면
  드롭을 `rejected / state-not-committed`로 거부한다. `onChange`를 호출하지
  않으며, 외부 목록 변경을 보존하고 삭제된 DOM을 다시 삽입하지 않는다.
- 실패한 이동은 기존 다중 선택과 Shift 선택 기준을 유지한다.
- 기본 드래그 제외 판정은 실제 편집 가능 상태를 사용한다. 빈 속성,
  `plaintext-only`, 상속과 `false` 하위 영역을 구분한다. 명시적 핸들과
  사용자 `ignore` 설정의 기존 우선순위는 유지한다.

필수 API 마이그레이션은 없다. 드래그 중 데이터를 갱신하는 앱은 해당 드롭이
거부될 수 있으므로 최신 목록에서 다시 드래그하도록 안내할 수 있다.
`state-not-committed`는 기존 사유지만 변경 이벤트 이전에도 발생할 수 있다.

## 변경 파일

구현·회귀 테스트는 [결함 수정 기록](./2026-10-02-drag-consistency-fixes.md)에
정리했다. 릴리즈 준비에서는 `package.json`과 `package-lock.json`의 루트
버전, 버전 검사 2건, `README.md`, `CHANGELOG.md`, 문서 색인과 한·영 가이드,
본 보고서를 갱신했다. 의존성 해석·peer 범위·exports·배포 파일 범위는 유지했다.

GIF는 2026-09-22 촬영본을 유지한다. 이번 변경은 기존 장면의 UI 구조를
바꾸지 않으며, 새로 촬영하거나 0.1.4에서 촬영한 것처럼 표시하지 않았다.

## 정식 artifact와 이후 단계

`publish.yml`이 정식 패키지 파일의 생성·검증·staging을 소유한다. 별도 로컬
tarball은 만들지 않았다. 정확한 파일 검증과 소비자 설치 검증을 통과하기 전에는
정식 Candidate 완료로 간주하지 않는다.

1. 승인 후 준비 브랜치를 원격에 반영하고 PR을 생성한다.
2. 보호된 main 병합과 필수 CI를 확인한다.
3. 승인된 `0.1.4`로 배포 워크플로를 실행한다. 해당 워크플로에서 한 번 생성한
   파일의 allow-list·라이선스·Gitleaks·소비자 검증을 수행한다.
4. trusted publisher staging 후 관리자가 npm 2FA로 승인한다.
5. 공개 버전·latest·신원·무결성·서명·provenance·소비자 검증을 마치고
   공개 시각과 배포 증거를 추가하여 Closed 상태를 기록한다.

## 잔여 리스크

- 기존 Safari 제목 드래그의 본문 선택 잔상은 해결 대상에 포함되지 않았다.
  이번 Chrome 직접 조작 및 WebKit 자동 검증을 실제 Safari 검증으로 확대하지 않는다.
- Galaxy 등 실기기 검증과 대규모 목록 활성화 지연 벤치마크는 수행하지 않았다.
- 이 기록은 배포 완료 증거가 아니며, 정식 파일·소비자·원격 CI·공개 후 검증은
  승인된 릴리즈 절차에서 수행해야 한다.
